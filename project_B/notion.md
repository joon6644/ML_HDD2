## 1. 서론

- [문제 및 필요성] 데이터센터 주력 저장 매체 [데이터센터 저장매체 현황], 고장 시 재구축 부하·데이터 손실 [디스크 고장 비용], 사후 대응 말고 사전 예측
- [문제의 성격] 임곗값을 미래 안 보고 미리 정해야 함, 허용 오탐 수준은 환경마다 다름 → 단일 운영점 말고 낮은 오탐률 구간을 따로 봐야 함
- [본 연구의 접근] Backblaze SMART, 시간순 분할, 10일 내 고장 예측, 임곗값은 val에서만 고정, 월 단위 산출 후 평균, 지표는 재현율·오탐률·ROC-AUC·pAUC
- [기여] ① 예측 모델 7종 성능 비교 ② 낮은 오탐률 구간에서의 탐지 성능 분석 ③ 예측 요인 분석
- [전개 예고] 2장 선행연구 / 3장 설계 / 4장 결과 / 5장 결론

## 2. 선행 연구

### 2.1 인공지능 기반 고장 예측

- [AI 도입 배경] 임곗값·규칙 기반 경보 → 센서 이력 기반 학습으로 넘어온 흐름 [규칙 기반 상태감시의 한계], 적용 분야 예시 한둘 [설비 고장 예측 ML 리뷰]
- [접근 방식] 분류(고장 여부) [고장 이진분류] / 회귀(잔여 수명) [잔여수명 회귀] / 이상탐지 [이상탐지 기반 고장예측]로 갈림, 본 연구는 분류

### 2.2 HDD 고장 예측

- [학습 기반 접근의 출발] SMART 정의는 도입부 한두 줄로만 [SMART 규격], 제조사 기본 임곗값 경보의 낮은 재현율을 지적한 초기 연구 [SMART 기본 경보 재현율] → 통계적 학습으로 전환된 계기 [초기 SMART 통계 학습]
- [모델 계열] 트리·SVM [SMART 트리·SVM 분류] → 딥러닝·시퀀스 모델 [SMART 딥러닝 예측] [SMART 시퀀스 모델]로 확장된 흐름, 자주 쓰이는 모델들
- [운영 관점 성능 보고] 오탐을 낮게 유지한 조건에서 탐지 성능을 보고하는 연구들 [저오탐 조건 탐지율 보고], 운영점 잡는 방식 [운영점 설정 방식]
- [해석 시도] SMART 속성 중요도를 본 연구들 [SMART 속성 중요도], 반복적으로 상위에 오는 속성 [HDD 예측 XAI]

## 3. 연구 방법

### 3.1 연구 개요

- [연구 목적] 과거 SMART 이력으로 향후 10일 내 고장 여부를 예측하는 이진 분류, 오탐률을 고려해 운영에서 쓸 수 있는 수준의 탐지 성능 확보
- [연구 방향성] 전체적인 실험 방향 및 xai 분석

### 3.2 데이터 및 전처리

- [데이터 소개] 백블레이즈 소개 [Backblaze 공개 데이터셋], 도시바 선정 이유, 제조사·모델마다 속성 집합이 달라 단일 모델 Toshiba MG07ACA14TA로 한정, 데이터 스펙, 2024-10-01 ~ 2026-03-31 (총 18개월)
- [전처리] raw사용, 메타데이터, 상수, 중복 컬럼과 결측치 비율 90% 이상 컬럼 및 중복 행을 제거하였다. 관측일 사이의 공백은 3일 이하이면 직전 값으로 보간하고, 4일 이상이면 불연속 구간이 하나의 입력 윈도우에 섞이지 않도록 별도의 시계열 세그먼트로 분리하였다. 이후 결측치가 남은 행과 고장 기록 후 다시 정상으로 기록된 HDD를 제거하였으며, 입력 윈도우는 각 세그먼트 안에서 구성하되 평가에서는 세그먼트가 분리된 HDD도 하나의 HDD로 취급
- [데이터 분할] 시간순 10-2-6, 예측은 한 달 단위 — 학습 2024-10-01~2025-07-30 (11,022,899행, 양성 0.033%), 검증 2025-07-31~2025-09-30 (1,943,792행, 0.030%), 테스트 2025-10~2026-03 (6개월)
- [레이블링] 그 달 안의 정보만 사용, 달 안에 고장 없으면 마지막 관측 10일 잘라내고 정상으로, 다음 달 고장은 다음 달에서 처리

### 3.3 모델

- [후보 모델] rf [RandomForest] /xgb [XGBoost] /lgbm [LightGBM] /mlp/lstm [LSTM] /gru [GRU] /tcn [TCN], 열화의 시간성 고려해 시퀀스 계열 포함, 원본 피처만, 불균형처리 없음, 하이퍼파라미터는 기본 구성, 시퀀스 입력창 14일
- [하이퍼파라미터 튜닝] 후보 비교에서 고른 GRU 대상, Optuna [Optuna] TPE [TPE] 50회, 목적함수는 검증 pAUC@FAR≤5% [부분 AUC], 대상은 hidden_size·num_layers·dropout·learning_rate·batch_size·weight_decay, 조기종료 적용, 분할·불균형 조건·예측 기간은 앞과 동일
- [예측 요인 분석] GRU는 트리 모델이 아니라 TreeSHAP 불가 → Integrated Gradients [Integrated Gradients], 기준점 0(min-max라 학습 구간 최솟값 = 가장 건강한 상태), 완결성 공리로 구현 검증, 테스트 구간 표본

### 3.4 평가 방법

- [평가 단위와 판정] 디스크 단위로 집계, 한 달 창 안의 최대 점수를 그 디스크의 점수로, 창 안에서 10일 내 고장이면 탐지 대상
- [임곗값] val에서 목표 오탐률에 해당하는 분위수로 결정, 테스트 구간에선 조정 없음
- [지표와 집계] 재현율·오탐률·ROC-AUC·pAUC@FAR≤5%, 유병률에 안 흔들리는 것만 사용, 월별로 산출 후 평균(달마다 고장 18~35대라 풀링하면 큰 달이 지배)

## 5. 결론

- [결과 요약] 도시바 18개월을 10-2-6으로 나눠 7종 비교 → pAUC 0.807~0.875로 계열 간 압도적 우위 없음, 사전 기준(pAUC@FAR≤5%)에 따라 GRU 채택. 검증에서 고정한 임곗값으로 6개월간 재보정 없이 운영했을 때 오탐률 1.28%에서 재현율 0.778. Integrated Gradients로 상위 기여 변수와 시점 확인
- [의의] 시간순 분할 + 검증 구간 임곗값 고정 + 월별 산출 후 평균이라는 조건이 실제 운영에 가깝고, 재보정을 전제하지 않는 보수적 조건에서 측정한 값. 유병률에 흔들리지 않는 지표만 써서 다른 기간·데이터셋과 비교 가능
- [한계 및 후속] 도시바 단일 모델·단일 시드·18개월 한 구간이라 이식성은 미검증, 입력 윈도우가 시계열 세그먼트를 넘지 않아 불연속 직후 구간은 짧은 이력으로 예측, 검증 임곗값을 평가 기간 내내 유지해 재보정 주기에 따른 성능 변화는 다루지 않음 → 다제조사 이식과 재보정 정책이 후속 과제
